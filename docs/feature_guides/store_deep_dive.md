# دليل صفحات المتجر التفصيلية

هذا الملف يكمل `store_management.md` ويغطي الصفحات التي تدير بيانات المتجر، إعداداته، تفاصيل المنتجات، المخزون، الأسعار، البراندات، والأقسام.

## الهدف

تجميع كل صفحات المتجر التي تظهر حول المنتج أو إعدادات المتجر في مرجع واحد:

- معرفة مسؤولية كل شاشة.
- تحديد الـ controller أو الـ repository الأقرب لها.
- توضيح السيناريوهات التي يجب فحصها عند أي تعديل.

## StoreEditScreen

المسار: `lib/features/store/screens/store_edit_screen.dart`

### ماذا تفعل الصفحة؟

صفحة تعديل بيانات المتجر الأساسية. تستقبل بيانات المتجر الحالية وتسمح بتعديل المعلومات النصية والصور وبيانات SEO حسب دعم الموديول.

### المدخلات

- كائن `Store`.
- صور الشعار والغلاف وصورة meta إن وجدت.
- ترجمات الاسم والوصف عبر قائمة اللغات.

### السلوك المتوقع

- تحميل القيم الحالية في الحقول.
- السماح بتغيير الشعار والغلاف.
- إرسال التحديث عبر `StoreController` ثم `StoreRepository.updateStoreBasicInfo`.
- تحديث `ProfileController.getProfile()` بعد نجاح الحفظ حتى تنعكس البيانات الجديدة في بقية التطبيق.

### فحص مهم

- تغيير الاسم بلغة واحدة لا يكسر بقية الترجمات.
- رفع صورة جديدة مع إبقاء صورة أخرى قديمة.
- حفظ بيانات meta بدون صورة meta جديدة.
- التعامل مع صيغة وقت التوصيل الحالية عند تعديلها.

## StoreSettingsScreen

المسار: `lib/features/store/screens/store_settings_screen.dart`

### ماذا تفعل الصفحة؟

تدير إعدادات التشغيل للمتجر مثل التوصيل، الطلب المجدول، الاستلام، أدوات الطعام، التوصيل المجاني، والوصفات حسب نوع الموديول.

### السلوك المتوقع

- عرض toggles مبنية على حالة المتجر الحالية.
- تغيير الحالة محلياً عبر `StoreController`.
- حفظ الإعدادات واستدعاء API المناسب.
- إظهار loading أو تعطيل الحفظ أثناء الطلب.

### فحص مهم

- تبديل أكثر من خيار ثم الحفظ مرة واحدة.
- الرجوع بدون حفظ لا يرسل تغييرات غير مقصودة.
- ظهور الخيارات الخاصة بالطعام فقط في موديول الطعام.
- ظهور الخيارات الخاصة بالصيدلية أو الوصفات فقط عند دعم الموديول.

## StoreSectionsScreen

المسار: `lib/features/store/screens/store_sections_screen.dart`

### ماذا تفعل الصفحة؟

تدير ترتيب وأسماء وتفعيل أقسام واجهة المتجر. تعتمد على:

- `StoreController.getStoreSections()`
- `StoreController.reorderStoreSections(...)`
- `StoreController.toggleStoreSectionActive(...)`
- `StoreController.updateStoreSectionCustomName(...)`
- `StoreController.saveStoreSections()`

### السلوك المتوقع

- تحميل الأقسام من السيرفر.
- دعم إعادة الترتيب.
- دعم تفعيل/تعطيل كل قسم.
- دعم تسمية مخصصة.
- إرسال payload مرتب يحافظ على `position` و`is_active` والاسم المخصص.

### فحص مهم

- إعادة ترتيب أول عنصر إلى آخر القائمة.
- تعطيل قسم ثم حفظه ثم إعادة فتح الصفحة.
- تعديل الاسم المخصص بقيمة فارغة أو طويلة.

## AddItemScreen

المسار: `lib/features/store/screens/add_item_screen.dart`

### ماذا تفعل الصفحة؟

شاشة إضافة أو تعديل منتج كاملة. هذه من أكبر شاشات المتجر لأنها تجمع الاسم، الوصف، الصور، التصنيف، السعر، المخزون، الخصم، الضريبة، الإضافات، الخصائص، الـ variations، tags، ومعلومات خاصة بنوع الموديول.

### المدخلات

- منتج اختياري عند التعديل.
- قائمة اللغات.
- التصنيفات.
- الإضافات والخصائص.
- بيانات VAT tax.
- مولد AI عند استخدامه.

### السلوك المتوقع

- في وضع الإضافة تبدأ الحقول فارغة مع قيم افتراضية.
- في وضع التعديل يتم preload لكل بيانات المنتج.
- تغيير التصنيف ينعكس على القوائم الفرعية إن وجدت.
- السعر والمخزون والخصم يتم التحقق منها قبل الحفظ.
- الصور ترفع عبر multipart.
- AI يمكنه اقتراح عنوان/وصف/بيانات أخرى أو استخراج بيانات من صورة.

### فحص مهم

- إضافة منتج بدون صورة عندما تكون الصورة مطلوبة.
- تعديل منتج مع variations موجودة.
- إدخال باركود يدوي وحفظه ثم البحث عنه من إدارة المنتجات.
- إضافة VAT متعددة ثم حذف واحدة.
- استخدام AI للصورة ثم مراجعة الحقول المعبأة.
- حفظ منتج بمخزون قليل والتأكد من ظهوره في صفحة `LowStockScreen`.

## ProductManagementScreen

المسار: `lib/features/store/screens/product_management_screen.dart`

### ماذا تفعل الصفحة؟

واجهة إدارة المنتجات المركزة التي تشمل البحث، السعر، المخزون، الفلاتر، وربط الباركود. التحديثات الأخيرة جعلت الباركود مثبتاً أعلى الشاشة، وأضافت إمكانية البحث بالرقم.

### ربط الباركود

`StoreRepository.getItemList(...)` يدعم الآن:

- `barcode`
- `minPrice`
- `maxPrice`
- `sort`
- `categoryId`
- `moduleId`

عند وجود رقم باركود، يتم تمريره كـ query parameter مشفر:

```text
&barcode=<encoded barcode>
```

### السلوك المتوقع

- إبقاء كاميرا/منطقة الباركود ثابتة أعلى صفحة إدارة المنتجات.
- السماح بإدخال رقم باركود يدوياً في البحث.
- عدم خلط البحث النصي مع الباركود بطريقة تمسح أحدهما بدون قصد.
- تحديث القائمة عند المسح أو الإدخال اليدوي.

### فحص مهم

- مسح باركود بالكاميرا.
- إدخال رقم باركود باليد والضغط على البحث.
- مسح قيمة الباركود والرجوع لكل المنتجات.
- البحث مع فلتر فئة.
- البحث مع حد سعر وفرز.
- فحص Android حقيقي لأن الكاميرا والأذونات لا تظهر بنفس السلوك على المحاكي/الويب.

## الاعتماديات المشتركة

- `StoreController`: الحالة، القوائم، الفلاتر، الصور، السعر، المخزون، الأقسام، البيانات المولدة.
- `StoreRepository`: API الخاص بالمنتجات، المتجر، الأقسام، المخزون، pending، VAT.
- `ProfileController`: تحديث بيانات المتجر بعد التعديل.
- `CategoryController` و`AddonController`: بيانات داعمة للمنتج.
- `AiController`: اقتراح البيانات وتوليدها من النص أو الصورة.

## قائمة فحص كاملة لصفحات المتجر

- فتح كل صفحة من navigation الطبيعي وليس فقط route مباشر.
- فحص صلاحيات الموظف لكل إجراء: عرض، إضافة، تعديل، حذف أو تغيير حالة.
- فحص الوضع العربي والإنجليزي للحقول المترجمة.
- فحص شاشة موبايل صغيرة وشاشة tablet/desktop إن كانت مدعومة.
- فحص offline أو فشل API برسالة واضحة.
- فحص عدم ظهور loading لا ينتهي عند فشل الطلب.
- فحص أن كل إجراء يحدّث القائمة السابقة بعد الرجوع.
