# شرح عام لمشروع Shoplanser Vendor

## الهدف من التطبيق

تطبيق `shoplancer_vendor` هو لوحة تشغيل للبائع/المتجر. يستخدمه صاحب المتجر أو الموظف لإدارة الطلبات، المنتجات، الأسعار، المخزون، الموظفين، المدفوعات، الاشتراكات، والإعدادات اليومية للمتجر.

التطبيق مبني بـ Flutter ويستخدم GetX لإدارة الحالة والتنقل. أغلب الشاشات موجودة تحت:

`lib/features`

وكل feature عادة يحتوي على:

- `screens`: صفحات المستخدم.
- `controllers`: منطق الحالة والعمليات.
- `domain/models`: نماذج البيانات.
- `domain/services` و`domain/repositories`: طبقة الاتصال والـ API.
- `widgets`: مكونات واجهة مخصصة للـ feature.

## الرحلات الأساسية

### 1. الدخول والتجهيز

يبدأ المستخدم من شاشة splash ثم ينتقل إلى تسجيل الدخول إذا لم يكن لديه جلسة محفوظة. بعد الدخول يتم تحميل profile وconfig وتحديد نوع الموديول، مثل متجر عادي أو rental.

الملفات الرئيسية:

- `lib/features/splash/screens/splash_screen.dart`
- `lib/features/auth/screens/sign_in_screen.dart`
- `lib/features/auth/screens/store_registration_screen.dart`
- `lib/helper/route_helper.dart`

### 2. لوحة التحكم

بعد الدخول، يدخل المستخدم إلى `DashboardScreen`. هذه الشاشة لا تعرض محتوى واحد فقط، بل تعمل كحاوية للتبويبات:

- الرئيسية.
- الطلبات.
- إنشاء طلب POS.
- المحفظة.
- القائمة.

على الديسكتوب، الراوت الأولي يذهب مباشرة إلى شاشة POS desktop.

### 3. تشغيل المتجر يوميًا

من الصفحة الرئيسية، يرى المستخدم اسم المتجر، QR، تحليلات الأعمال إذا كانت صلاحية المحفظة مفعلة، والطلبات الجارية مع فلاتر حسب الحالة.

### 4. المنتجات والمخزون

Feature `store` هو أكبر جزء في التطبيق. يغطي:

- بيانات المتجر.
- إضافة وتعديل المنتجات.
- إضافة سريعة للمنتجات.
- إدارة الأسعار.
- إدارة الحالة.
- البحث بالاسم والباركود.
- المنتجات غير النشطة والمعلقة وقليلة المخزون.

### 5. إنشاء الطلب

Feature `pos` يغطي إنشاء طلب من داخل التطبيق عبر شاشة POS للموبايل أو الديسكتوب، ويشمل البحث، الباركود، السلة، العميل، والإرسال.

### 6. الطلبات

Feature `order` يغطي سجل الطلبات، تفاصيل الطلب، الفاتورة، واختيار البدائل عند الحاجة.

### 7. المال والاشتراك

Features `payment`, `disbursement`, و`subscription` تغطي المحفظة، السحب، سجل المدفوعات، الاشتراكات، وتجديد/تغيير الخطة.

## التنقل

الملف المركزي للتنقل هو:

`lib/helper/route_helper.dart`

يحتوي على:

- أسماء الـ routes.
- دوال بناء route مع query params.
- قائمة `GetPage` التي تربط route بالصفحة.

عند توثيق أي صفحة، يجب الرجوع لهذا الملف لمعرفة من أين تفتح الصفحة وما اسم route الخاص بها.

## إدارة الحالة

التطبيق يعتمد على GetX:

- كل feature تقريبا لديه controller.
- الصفحات تستخدم `GetBuilder` أو `Get.find`.
- العمليات مثل تحميل قائمة المنتجات أو تسجيل الدخول تنفذ عبر controller ثم service/repository.

مثال:

- `AuthController` لتسجيل الدخول والتسجيل.
- `StoreController` للمنتجات والمتجر.
- `OrderController` للطلبات.
- `PaymentController` للمحفظة.

## ملاحظات مهمة للتوثيق

- الشرح يجب أن يكون بالعربية.
- أسماء الملفات والكلاسات تبقى كما هي بالإنجليزية.
- عند وجود bottom sheet أو dialog مهم، يوثق تحت الصفحة التي تفتحه.
- عند وجود اختلاف بين موبايل وديسكتوب، يوثق صراحة.
- لا يتم توثيق implementation الداخلي الطويل إلا بقدر ما يساعد على فهم سلوك الصفحة.
